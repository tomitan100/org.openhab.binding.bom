# Australian BOM Weather Binding — rebuilt for openHAB 5.x

This is a rebuild of [tomitan100/org.openhab.binding.bom](https://github.com/tomitan100/org.openhab.binding.bom)
(Australian Bureau of Meteorology weather forecast + radar/satellite image binding)
so that it installs and runs on **openHAB 5.x (including 5.2)**.

The original jar was built against the openHAB 3.2 core. Its OSGi manifest imports
`org.openhab.core.*` packages with a `[3.2,4)` version range, so on openHAB 4/5 the bundle
fails to resolve and every thing shows up broken. This rebuild compiles against the
openHAB core 5.0 APIs, so the generated import range `[5.0,6)` resolves on any 5.x runtime.

## What changed

- **Build**: standalone Maven project (no openhab-addons parent needed). Compiles against
  `org.openhab.core.bundles:org.openhab.core(.thing):5.0.0` from the openHAB Artifactory repo,
  Java 21 target (`openHAB 5` baseline), OSGi manifest generated by `maven-bundle-plugin`.
- **commons-net is embedded** in the jar (`Embed-Dependency`), so the binding resolves no
  matter which commons-net version (if any) your runtime ships.
- **TIFF support** (Himawari-8 satellite images) now uses the JDK's built-in ImageIO TIFF
  reader — the old third-party twelvemonkeys bundles are no longer needed.
- **Bug fixes carried over from the original code**:
  - missing `break` in the forecast switch statement caused `precis` to be briefly
    overwritten by the icon code;
  - null-safe refresh intervals / GIF delay (no NPE if a config value is cleared);
  - connect/read timeouts on all FTP fetches so a stalled BOM server can't hang a job;
  - periodic per-cycle log spam demoted from INFO to DEBUG.
- Thing/channel definitions (`OH-INF`) are unchanged — existing things, items and channels
  keep working after replacing the jar.
- i18n placeholder file replaced with real English strings.

## Requirements

- openHAB 5.x, Java 21+
- Fonts installed on the host if "Embed local timestamp" is used for images
- To build: JDK 21+ and Maven 3.9+

## Build

```bash
mvn clean package
```

The result is `target/org.openhab.binding.bom-5.2.0.jar`.

## Install

1. Remove the old binding jar from `${OPENHAB_CONF}/../addons` (or your addons directory).
2. Copy `target/org.openhab.binding.bom-5.2.0.jar` into the addons directory.
3. Restart openHAB (or run `bundle:start org.openhab.binding.bom` from the Karaf console).
4. Your existing `bom:weather` / `bom:image` things will pick up automatically.

## Configuration

Unchanged from the original — see the
[original README](https://github.com/tomitan100/org.openhab.binding.bom#readme) for the full
configuration guide (observation/forecast product IDs, radar image layers, etc.).
Sample items/sitemap are in [`doc/bom.items`](doc/bom.items) and [`doc/bom.sitemap`](doc/bom.sitemap).

Quick check that BOM's public feeds are still reachable:

```bash
curl -s -o /dev/null -w "%{http_code}\n" ftp://ftp.bom.gov.au/anon/gen/fwo/IDW14199.xml
```

## Troubleshooting

If things stay UNINITIALIZED after install, check the bundle state in the Karaf console
(`ssh -p 8101 openhab@localhost`, then `bundle:list | grep bom`). If it shows `Installed`
instead of `Active`, run `bundle:diag org.openhab.binding.bom` to see the unsatisfied import.
